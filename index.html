자동화 정책

내부 워커와 외부 봇에 동일한 정책, 예산, 정지 상태가 적용됩니다.

POLICY v1

운영 모드

AUTO는 허용된 정책 범위에서 매번 승인 없이 실제 트랜잭션을 전송합니다.

지갑 서명키와 Factory 주소는 서버 환경에서 설정합니다. 메인넷 설정이 검증되지 않으면 AUTO 발행은 보류됩니다.

수령 방식은 새 초안과 그 발행에 적용됩니다. 기존 초안과 이미 고정된 발행 정보는 바뀌지 않습니다.

후보 선정 기준

발행 한도 · 오류 제어

비용 예약은 서버에서 원자적으로 처리합니다. 전송 직전 신선도, 점수, 잔액, 예산, 정지 상태를 다시 검사합니다.

거래 개시 · 유동성

DEX 미연결

공식 DEX가 검증된 메인넷과 서버의 유동성 옵션이 모두 활성화되어야 합니다. 각 발행 지갑 방식에서는 해당 지갑이 토큰과 ETH를 공급하고 LP 지분을 수령합니다. 공급 ETH와 가스에 별도 예산이 적용되며, 토큰 생성 후 유동성이 확인되어야 거래가 개시됩니다.

저장 시 새 정책 버전과 감사 기록이 생성됩니다.

API 요청 예시

운영 환경에서는 별도 봇 키에 필요한 권한만 부여하세요. 키를 URL이나 로그에 넣지 않습니다. 

curl -X POST http://localhost:8787/api/launches \
  -H "Authorization: Bearer $BOT_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: unique-request-uuid" \
  -d '{"draftId":"YOUR_DRAFT_ID"}'

응답에 포함된 작업 ID로 상태를 조회하세요. 결과가 불명확하면 동일한 키로 재시도하고 작업 및 온체인 상태를 확인합니다.
